# 2026-09-14

## 创建 Chrome 扩展：自动画中画（pip-chrome-plugin）

从零搭了一个 MV3 扩展：视频播放中切到其他标签页 → 自动进入画中画；切到其他应用不触发；带控制面板开关。

**关键设计决策**

- **区分「切标签页」与「切应用」**：内容脚本监听 `visibilitychange`，真正判定交给 Service Worker 查
  `chrome.tabs.query({active:true, windowId})`。切应用时活跃标签页不变 → 不触发；切标签页时活跃页易主 → 触发。
  这是唯一能精确满足「只响应切标签页」的做法（`document.hasFocus()` 两者都失焦，区分不了）。
- **Chrome 的 `requestPictureInPicture()` 有用户手势限制**（`document` 无 transient activation 时抛 `NotAllowedError`）。
  通常用户点过「播放」就满足；为此加了默认关闭的「兼容模式」，在首次失败后于下一次手势做一次
  进入+立刻退出的预热。
- **不设 `video.autoPictureInPicture = true`**：Chrome 内置自动画中画在切应用时也会触发，会违反需求②。
- **视频挑选打分**：有声 +1000、时长越长加分、面积越大加分、在视口内加分，避免选中背景动画等装饰性视频。
- `manifest` 只申请 `storage` 权限 + 全站内容脚本，不申请 `tabs`（查活跃标签页的 id/windowId 无需该权限）。

**文件**：manifest.json / background.js / content.js / popup.{html,css,js} / tools/gen-icons.mjs / icons/ / docs/

**坑与结论**

- 无头 Chrome 的 `--force-prefers-color-scheme=dark` 不生效。要看深色态预览，就把 popup.css 里
  `@media (prefers-color-scheme: dark)` 块抽出花括号单独成一份 css 再渲染。
- 图标必须是 PNG（manifest 的 icons 不支持 SVG）；用 Node 手写 PNG 编码即可，无需第三方依赖。

## 追加：构建与打包命令

新增 `package.json` 脚本，用户要求把相关文件打包成压缩包放到 `build/`，并把 `build/` 写进 `.gitignore`。

- `npm run icons` → `tools/gen-icons.mjs`
- `npm run package` → `tools/package.mjs`
- `npm run build` → 上面两步

实现要点：

- `tools/lib/zip.mjs` 是手写的 ZIP 写入器（local header + central directory + EOCD，
  deflate 用 `zlib.deflateRawSync`，压缩无收益时退回 store）。`gen-icons.mjs` 的 CRC32 也改为复用这里的实现，去掉重复代码。
- `tools/package.mjs` 用**白名单** `INCLUDE` 决定打什么（manifest/background/content/popup/icons），
  并会解析 manifest 反查引用，若引用了白名单外的文件就报错退出——避免悄悄产出坏包。
- 用户说过「可以依赖三方依赖，只要能打包」，所以第三方是允许的；但实测手写 ZIP 就够，且免去
  `npm install`，因此仍保持零依赖。若日后想换成 `archiver` 之类，直接替换 `createZip` 调用即可。

验证方式（都通过）：

- `unzip -t` 无错；解压回读 10/10 文件与源文件字节级一致。
- 故意让 manifest 引用 `ghost-file.js` → 打包按预期报错并退出码 1。
- 抽取 CRC32 后重跑图标生成，四个 PNG 与重构前哈希完全一致。
